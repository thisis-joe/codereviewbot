# 운영과 복구

## 확인 명령

```sh
docker compose ps
docker compose logs --tail=50 controller runner n8n
curl --fail http://localhost:18092/healthz
```

`/internal/health`는 `.env`의 INTERNAL_TOKEN에 대한 Bearer 인증이 필요하다. 작업 수·실패 수·현재 실행 여부를 제공한다.
로그에는 작업 ID·단계·분류된 실패 원인만 남긴다. Codex 원문 대화나 Git 자격 증명을 출력하지 않는다.

## 중복과 장애

- 외부 이벤트를 DB에 기록한 뒤 응답한다. GitHub는 실패한 전송을 항상 자동 재전송하지 않으므로 1분 복구 조회도 사용한다.
- 전역 작업 lease로 한 번에 하나를 실행하며 15초마다 갱신한다. 90초 동안 갱신하지 못하면 재선점할 수 있다.
- 선점 토큰이 바뀌면 이전 프로세스의 결과 저장·게시를 거부한다.
- 댓글 쓰기는 무작정 자동 재전송하지 않는다. 60초 후 실제 플랫폼의 봇 소유 마커를 대조해 다음 시도를 한다.
- 단계별 최대 3회 시도 후 실패로 남긴다. 인증·설정을 고친 다음 `/reviewbot full` 또는 인증된 `/internal/retry`에 작업 ID를 전달한다.
- 플랫폼 쓰기 직전 SHA를 확인하지만 원격 푸시와 쓰기를 원자적으로 잠글 수는 없다. 모든 코드 댓글은 검토한 커밋·diff 버전에 연결한다.

## 데이터와 백업

`database`에는 작업·보고서·피드백과 별도 n8n DB가 있고, `codex-auth`에는 봇 전용 인증이 있다.
`.env`, n8n encryption key, DB dump, Codex 전용 인증과 터널 자격 증명을 각각 보호해 백업한다.
원문 Git 캐시는 컨트롤러 전용 볼륨이며 실행기에 공유하지 않는다. 소스 스냅샷은 7일 후 복구 작업에서 정리한다.
작업·중복 방지·피드백 메타데이터는 자동 삭제하지 않는다. 운영 용량을 관찰하고 명시적 보존 정책을 정한 뒤 정리한다.

## Mac mini

Colima와 프로젝트를 다른 스택과 분리해 운영한다. 서버로 사용할 때는 로그인 후 Colima와 `docker compose up -d`를 실행하도록 macOS 로그인 항목/launchd를 설정한다.
필요하면 `caffeinate -s`로 전원 연결 중 시스템 잠자기를 방지한다. 이 구현은 시스템 전체 절전·로그인 설정을 자동 변경하지 않는다.
Mac이 꺼져 있거나 네트워크가 끊겼다면 복구 후 최신 열린 PR/MR부터 재동기화한다. 중간 푸시를 모두 재생하지 않는다.

Colima VM의 디스크는 Mac 호스트의 여유 공간과 별개다. `colima ssh -- df -h /var/lib/containerd`로 확인한다.
이미지 빌드와 PostgreSQL 초기화 전에 충분한 공간을 확보한다. 빌드 시 8 GiB 이상 여유를 권장한다.
공간 부족 오류가 나면 이 프로젝트를 정지하고, 소유가 확인된 이전 이미지·빌드 캐시만 정리한다.
다른 프로젝트를 포함하는 전역 prune이나 볼륨 삭제는 복구 명령으로 사용하지 않는다.

## 현재 한계와 검증 범위

- 모델 리뷰는 정적 분석이다. 실제 프로그램 실행 성공이나 완전한 보안을 보장하지 않는다.
- SDK/CLI 버전은 고정한다. 업데이트 때 MCP 도구 목록, 셸 비활성화, JSON 출력과 실패 처리 테스트를 재실행한다.
- 전용 GitHub App/토큰의 인스턴스별 권한, 실제 GitLab 버전의 signing 지원, suggestion 렌더링은 실연동 단계에서 확인한다.
- 민감 파일 제외와 알려진 자격 증명 마스킹은 방어 수단이며 모든 형태의 하드코딩된 비밀을 탐지하는 보장은 아니다.
- 기존 CI만 읽는다. CI가 없으면 `미실행`, 로그 접근이 안 되면 `확인 불가`다.
- 자체 CodeRabbit 동급 탐지율을 주장하지 않는다. 유효 지적·놓친 결함·중복·수정 채택·지연을 실제 변경으로 평가한다.
