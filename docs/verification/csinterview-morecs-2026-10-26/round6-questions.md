- B 해설: 종류 내부의 공정성과 종류 사이의 공정성을 혼동했습니다. **리뷰 종류 자체가 선택되지 않으면** 내부 접수 순서는 실행 기회를 만들지 못합니다.
- C 해설: 재시도 비용 제한과 최초 실행 기회 보장을 혼동했습니다. **선택되지 않은 작업**에는 재시도 횟수 제한만으로 진행 기회가 생기지 않습니다.
- D 해설: 대기 작업 수가 유한하고 각 실행이 끝난다면, 앞선 작업을 처리할 때마다 자신의 차례가 가까워집니다. 새 작업의 추월을 막는 것이 이 보장의 핵심입니다.

#### 꼬리11 (↳ 꼬리6) · advanced · 정답 B · src/learning-command.ts:278

코드는 외부 댓글 게시 전에 작업 임대의 유효성을 확인하며, 임대가 만료된 작업은 다른 작업자가 다시 맡을 수 있습니다. 실패 시점만 바꾸어, 첫 작업자가 확인을 통과해 게시를 요청한 뒤 임대가 만료되고 요청 처리는 계속 지연된다고 가정하겠습니다. 두 번째 작업자가 아직 생성된 댓글을 찾지 못한 경우, 임대가 제공하는 보장에 대한 판단으로 옳은 것은 무엇인가요?

- A. 게시 직전 임대 확인에 성공했으므로 외부 요청이 완료될 때까지 임대도 유효합니다.
- B. 임대 만료가 이미 보낸 외부 요청을 취소하지는 않으므로 두 작업자의 게시가 겹칠 수 있습니다.
- C. 이전 작업자의 데이터베이스 쓰기가 소유자 검사로 거절되면 외부 댓글 생성도 함께 거절됩니다.
- D. 외부 요청 지연의 상한을 몰라도 임대 시간을 충분히 길게 고정하면 게시 중첩을 제거할 수 있습니다.

해설: 임대(lease)는 제한된 시간 동안만 작업 소유권을 인정하는 방식이며, 만료된 소유자의 실행이나 이미 전송한 요청을 자동으로 중단시키는 장치는 아닙니다. 외부 요청이 임대보다 오래 지속되면 새 소유자와 이전 요청이 동시에 외부 부수 효과를 만들 수 있습니다. 따라서 임대 확인만으로는 댓글 생성 전체에 대한 상호 배제(mutual exclusion)가 보장되지 않습니다. 외부 시스템이 요청 식별자별 생성을 원자적으로 중복 제거하거나 이전 소유자의 효과를 확실히 차단한다면 결론이 달라집니다. 이번 변경의 최종 게시 호출은 로컬 임대 확인과 외부 댓글 생성 사이의 보장 경계를 드러내는 지점입니다.

- A 해설: 시점의 유효성 확인과 구간 전체의 보장을 혼동했습니다. 임대 확인은 **확인한 순간의 소유권**을 검사할 뿐, 외부 요청 동안 만료 시간을 멈추지 않습니다.
- B 해설: 소유권의 만료와 진행 중인 외부 요청의 종료는 별개의 사건입니다. 두 번째 작업자가 소유권을 얻어도 첫 요청이 나중에 댓글을 생성할 수 있습니다.
- C 해설: 데이터베이스의 조건부 쓰기와 외부 시스템의 동작을 혼동했습니다. **로컬 소유자 검사**는 그 검사에 참여하지 않는 외부 댓글 생성까지 제어하지 않습니다.
- D 해설: 위험 감소와 보장을 혼동했습니다. **지연 상한이 없는 조건**에서는 어떤 고정 임대 시간보다 오래 걸리는 요청도 가능하므로, 시간을 늘리는 것만으로 중첩을 제거할 수 없습니다.
